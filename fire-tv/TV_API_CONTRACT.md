# RentReady Vision - Fire TV API Contract

Status: Proposed v1
Branch: amazon-2026
Scope: Read-only inspection viewing

## Goal

Provide a small TV-specific API representation of real,
completed RentReady Vision inspections.

Do not expose the entire existing inspection report.

## Endpoints

GET /api/tv/inspections
GET /api/tv/inspections/{inspection_id}
GET /api/tv/inspections/{inspection_id}/rooms
GET /api/tv/inspections/{inspection_id}/findings
GET /api/tv/findings/{finding_id}
GET /api/tv/inspections/{inspection_id}/briefing

All endpoints are GET-only.

## Inspection list

Response includes only explicitly authorized,
completed inspections.

Fields:
- id
- property_name
- status
- finding_count

The initial version uses an approved inspection
allowlist. Do not scan and expose the entire database.

## Property overview

Fields:
- id
- property_name
- status
- finding_count
- severity_counts

Severity counts are computed from presented findings.

## Room summary

Fields:
- id
- name
- finding_count
- finding_ids

Absence of findings does not prove a room was inspected
or confirmed clear.

## Finding summary and detail

Fields:
- id
- inspection_id
- room
- title
- severity
- confidence
- timestamp_seconds
- description
- recommended_action
- evidence_image_url
- evidence_video_url

Finding IDs must resolve unambiguously to one authorized
inspection. Raw database and S3 identifiers are private.

Nullable fields must remain null if source data is absent.

## Severity mapping

Fix before renting -> high
Review recommended -> medium
Cosmetic -> low
Unrecognized values -> unknown

Severity mappings must preserve source meaning.

## Property briefing

Fields:
- headline
- priority_finding_id
- priority_room
- recommended_action
- medium_count
- disclaimer

The briefing is derived from existing reported findings,
not generated by an additional model invocation.

Priorities should use documented severity ordering.
All reported conditions require appropriate human review.

## Evidence handling

Evidence URLs may be null.

Only short-lived authorized access is permitted.

Never expose:
- S3 bucket names or object keys
- Internal processing metadata
- AWS credentials
- Operator authentication tokens
- Raw detector candidates
- Complete source reports

Expired or missing video must not prevent viewing
a retained inspection report.

## Authentication and access

All /api/tv routes must be protected before registration
in a remotely accessible backend.

Never embed the privileged operator token in the TV APK.

TV access must use a restricted, revocable mechanism.
Validate inspection authorization on every endpoint.
Protect against cross-inspection finding access.

Temporary public judging mode does not automatically
authorize access to the TV API.

Use HTTPS for remotely accessed services.

## Real inspection acceptance criteria

1. One authorized real inspection is COMPLETE.
2. Its saved report is available.
3. TV endpoints return only approved fields.
4. Severity and room mappings are verified.
5. Missing evidence returns null or a safe unavailable state.
6. Unauthorized requests are rejected.
7. The TV client retrieves and displays the real inspection.

## Exclusions

No upload endpoints.
No processing triggers.
No write operations.
No account management.
No dashboards or admin controls.
No new AI inference required for basic retrieval.

## Current implementation status

Contract proposed.
Backend routes not yet implemented.
TV client not yet connected to real inspections.
AWS deployment not yet modified.
